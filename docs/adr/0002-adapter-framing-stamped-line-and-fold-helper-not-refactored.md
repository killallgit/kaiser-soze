# The adapter framing, the stamped tap line and the test fold helper are not refactored

The architecture review of exchange recording (October 2026) named three more candidates. After reading the code we decided to leave each as it is. The review's other findings were built.

1. **Parser framing is not moved under the `Adapter` seam.** The Claude and Codex parsers (`src/adapter/claude/parser.rs`, `src/adapter/codex/parser.rs`) repeat about 20 lines: three fields (`RequestBuffer`, `response_encoded`, `SseSplitter`), the request-body arm, the response-head line and a `stream_events` skeleton. The gating differs in substance. Claude parses SSE only when the content type says event-stream and sends any other reply to unparsed. Codex parses any unencoded body and also reads WebSocket messages. Empty and unreadable requests differ too. A shared module would carry those differences as parameters, so its interface would be nearly as large as its implementation, and the deletion test says it only moves the code. `ShapedParser` frames responses differently from both. Revisit if a third adapter repeats the same gating.
2. **The tap `Line` is not split into an unstamped and a stamped type.** `Recorder::line` is the only non-test site that builds a tap `Line`, and the unstamped state is documented on the `sequence` field (zero before emission). `run_id` and `sequence` are set by the `prepare` closure passed to `Sink::open_preparing`, which mutates the same `Line`. Two types would need a change to the `FnMut(&mut T, u64)` signature or the writer loop, and stamping must stay in the single tap writer, as `docs/common-format.md` and the `Line::sequence` comment require.
3. **The test fold helper is not replaced.** `fold` in `tests/proxy/support.rs` does not re-implement the assembler: it runs the production `Assembler` over the live reply events, and the three call sites compare the result with the record the tap wrote on every key except `conversation`, `step` and `turn`. That is the only test that proves the live lines and the finished record agree. What it duplicates is a decoder of about 15 lines from JSON to `Event` (`stream_event`). A direct assertion at its three call sites would be weaker, and deleting `fold` would lose the check.
